# Architecture

Hosted on **Google Cloud**, following the same pattern as Observa Custódia: a Next.js site on Cloud Run, Firebase
Hosting in front for the custom domain, HTTPS and CDN, deploys from GitHub Actions without service account keys,
and secrets in Bitwarden. The difference is that here the data changes every day, so there is a **scheduled
pipeline** that collects, processes and generates the PDFs.

Everything runs in `southamerica-east1` (São Paulo). Besides lower latency, running in Brazil reduces the risk of
the blocking or throttling that some Brazilian public sites apply to traffic from outside the country.

```
  Cloud Scheduler (daily)
        │
        ▼
  ┌──────────────── Cloud Run Job: pipeline (Python) ────────────────┐
  │ 1. Collect        2. Normalize        3. Curation     4. Generate │
  │ APIs and files  → master registry, → approved items → JSON per   │
  │ (raw responses     votes, bills,      (YAML in repo)   politician│
  │  kept)             lawsuits, topics                    + 1-pg PDF│
  └───────┬──────────────────────────────────────────────────┬───────┘
          ▼                                                  ▼
  Cloud Storage: raw/  processed/ (Parquet)           Cloud Storage: site/ (JSON) and pdf/
                                                             │
          ┌──────────────────────────────────────────────────┘
          ▼
  Cloud Run: frontend (Next.js) ◄── Firebase Hosting (domain, HTTPS, CDN) ◄── visitor
  Cloud Run: backend (FastAPI): correction and right-of-reply form
```

At the end of each run, the pipeline publishes a new Firebase Hosting release, which clears the CDN cache
(Observa Custódia does the same after each frontend deploy).

## Components

| Part | Choice | Notes |
|---|---|---|
| Pipeline | **Python 3.13 + uv**, running as a **Cloud Run Job** triggered by **Cloud Scheduler** | httpx, tenacity, polars, pydantic. The same code runs locally with `uv run`. No 6-hour limit per run and no dependency on a runner in the US |
| Storage | **Cloud Storage** (raw responses, Parquet, site JSON, PDFs) | DuckDB reads the Parquet directly for the transformations |
| Supporting data | **BigQuery** (optional) | Query the public tables of Base dos Dados (Chamber, Senate, TSE) in the same project to load the history. Free up to 1 TB of queries per month |
| Frontend | **Next.js** (`output: "standalone"`) in Docker on **Cloud Run** | One page per politician, search, methodology page. Reads the JSON from the bucket with caching |
| Domain and CDN | **Firebase Hosting** forwarding everything to Cloud Run | Cloud Run does not support custom domains in `southamerica-east1` |
| PDFs | Generated in the pipeline with **Playwright (Chromium)** from the same HTML/CSS as the page; stored in Cloud Storage | Pre-generated: the site just passes the file through (private bucket) and the Firebase CDN caches the response |
| Backend | **FastAPI** on **Cloud Run**, with rate limiting (slowapi) and email sending | Only for the correction and right-of-reply form in the MVP. Later, a curation dashboard |
| Search | Next.js route `/api/busca`, with the index in memory | Index generated by the pipeline (`index.json`, 862 names in v1). Server-side so it stays viable with the TSE's ~485,000 candidacies |
| CI/CD | **GitHub Actions** + **Workload Identity Federation** + **Artifact Registry** | Tests before deploy: pytest, Vitest, Playwright (smoke and accessibility) |
| Secrets | **Bitwarden Secrets Manager** (`bws`) | Portal da Transparência API key, DataJud key, Claude API key, SMTP. They become Cloud Run environment variables on each deploy |
| AI | Claude API, small model, only for new items | Summarize speeches and news by topic; everything is reviewed before publishing |
| Curation | **YAML files in the repository**, reviewed through pull requests | Key votes, hot topics, confirmed lawsuits, reviewed positions |

## Cost
It is no longer zero cost, but close to it: Cloud Run with `min-instances=0`, one daily job and a few GB in Cloud
Storage fit in the free tier or come to a few reais a month. The project needs billing enabled (Firebase Hosting
forwarding to Cloud Run requires the Blaze plan). The largest variable cost is likely to be AI.

### Draft v1 (implemented on November 1, 2026)

`uv run puxa profile <id>` generates `data/site/html/<id>.html` and `data/site/pdf/<id>.pdf`. Contents: photo,
name, roles, hot topics, key votes and legislative output. Assets, lawsuits and statements come in later
versions. Choices made in v1:
- Neutral vote colors (blue for Sim, terracotta for Não), no green and red, so as not to suggest right or wrong.
  The vote is also written out, so color is not the only cue.
- "Sem registro" ("no record") in the Chamber means absent or not in office on that date. The profile does not
  state the reason.
- Civil name only when it comes from the TSE, which respects the social name. The Chamber's registered name is not
  shown.
- All-caps TSE names are reformatted ("TARCÍSIO" → "Tarcísio"); acronyms without vowels stay as they are ("JHC").
- If the content does not fit on one page, the profile uses a compact version. All 862 profiles fit.
- Inter font. In the production image, install the font and Chromium (`playwright install chromium`). In this
  environment, the pipeline uses the preinstalled Chromium (set `PUXA_CHROMIUM` to point to another one).
- Photos embedded in the PDF (180 KB per profile on average). Reducing photo resolution is a pending optimization.

## Site v1 (November 1, 2026)

- `site/`: Next.js 16, App Router, `output: "standalone"`. Three screens: search (name + photo), the person's
  profile, and the PDF download. No database: it reads the files that `uv run puxa site` generates in
  `data/site/web/`.
- Routes: `/` (search, also works without JavaScript via `?q=`), `/ficha/{id}`, `/ficha/{id}/pdf`, `/foto/{id}`,
  `/api/busca?q=`. The public URLs are in Portuguese.
- Data: in production it comes from the `{project}-dados/web/` bucket, read with the Cloud Run service account
  token (private bucket); in development, from the local folder. In-memory cache of 10 minutes.
- Kept out of search engines (`noindex`) while the data is being validated.
- Step-by-step GCP setup through the console: [deploy.md](deploy.md).
